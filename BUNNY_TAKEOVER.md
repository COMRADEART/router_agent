> **Historical report.** The current running Windows release is **v10**, verified on October 2, 2026. Its real agent discovery/execution, live events, routing, Stop, reconnect and phone evidence are in [BUNNY_M2_REPORT.md](BUNNY_M2_REPORT.md). This report was produced before implementation. Existing work is retained. Recovery material is in `artifacts/bunny-takeover/`: a binary Git patch and an archive of modified/untracked source files. No reset, checkout, clean, or commit was performed.

1. **Repository architecture.** React 19 / TypeScript / TanStack Start + Router, Vite 8, Nitro, Tailwind 4, Zustand, Recharts. `src/routes/index.tsx` mounts `components/island/workspace.tsx` through `island.tsx`. `use-island.ts` owns tasks/projects/preferences. `orch/router.ts` classifies and scores. TanStack server functions in `exec.ts` call `exec.server.ts`. Auth/Postgres helpers exist but are unused. Older `jev/` and `quorum/` modules remain, outside the active entry path. Windows `install/` wraps standalone Nitro. Android is a Java WebView client, not an agent runtime.
2. **Git/local changes.** Branch `main`, baseline `eae148b`. Modified before takeover: `.gitignore`, package.json, smoke/PWA test scripts, island entry, OG identity, executor/telemetry, generated routes, store/styles, startup and Vite config. Untracked: reports, Android source, desktop installation/package scripts, workspace UI, executor tests, JEV icons. All belong to prior work and must be preserved.
3. **Tests.** Fresh `npm test`: script suite 198/198; application suite 63/63; **261 passed, zero failed**. Log: `test-results/bunny-takeover-tests.log`. Prior reports say build/typecheck/browser/Ollama passed; those are historical evidence, not fresh takeover verification.
4. **Ollama path.** Browser route/review → approval → `runExecutor` → `execute` → `/api/tags` probe → selected model validation → `/api/generate`, non-streaming, 120-second abort → result. In-memory controllers support task-specific stop and duplicate refusal. Preserve this bounded executor; Host wraps it initially. Ollama text generation has no filesystem/terminal capability.
5. **Router.** Keyword classifier; static task/context/speed/local capability priors; modes change weights; availability multiplier and active-job penalty. Alternatives/reasons and heuristic confidence exist. Unavailable/auth-required providers can still win. Privacy is only a preference; hard constraints are absent. Confidence is not calibrated.
6. **Telemetry.** Node OS CPU deltas, clock fallback, total/free RAM. NVIDIA CLI query supplies utilization/VRAM/temperature/power. Current parser assumes one GPU. CPU temperature is explicitly unavailable. Sampling currently follows UI polling; Host must own its rolling buffer.
7. **Adapters.** Working Ollama generation/probe. Codex/Claude launch refusal stubs; Cline/Cursor extension slots. No owned coding-agent sessions yet.
8. **Codex/Claude discovery.** None in app: browser constructs hardcoded credential-required states. Takeover environment PATH resolves real `codex.exe` and `claude.exe`; OpenCode npm shim is present. Installation/auth/readiness must be established through bounded CLI probes, not assumptions. No quota API is presently integrated.
9. **Move to Host.** Task IDs/lifecycle, route snapshots, approvals, execution, cancellation, output/logs, projects, durable audit/events and outcome statistics. Browser keeps theme, unsent drafts and view selection. Hydration must stop converting running tasks to failed. Legacy history needs idempotent import without launching any job.
10. **Proposed boundary.** Separate Node Windows Host (native SQLite; Node >=22.13), TaskManager, event journal, provider registry/adapters, process ownership, project registry, telemetry and learning. Loopback authenticated HTTP API, cursor replay/SSE, with same-origin application bridge. UI is a consumer. Remote gateway later requires pairing, revocation, TLS and authorization; no unauthenticated internet exposure.
11. **Files.** Add `src/lib/bunny-host/` contracts, persistence, manager, discovery/adapters and HTTP service; `scripts/bunny-host.mjs`, Host lifecycle scripts and regression/integration tests. Add bridge under `orch/`, adapt store and retain dashboard. Extend desktop package/launch scripts with independent Host startup. Add widget/native startup only after lifecycle is verified. Update active metadata/UI/Android label to Bunny-A without renaming compatibility storage/package identifiers destructively.
12. **Sequence.** A durable Host + UI reconnect; B safe discovery; C real owned CLI sessions; D fail-closed constraints and evidence scoring; E native top-center glass widget; F outcomes/performance + gated policy replay; G TLS paired phone gateway and notifications; H optional integrations. Each passes tests before the next. Continue independent work when external dependencies block a capability.
13. **Risks.** UI/server hot reload must not create competing owners; SQLite must stay local and separate from serverless deployment. Native Node SQLite requires suitable runtime. CLI versions/event formats/auth vary. Abrupt Host loss differs from UI disconnection: no PID-based killing without ownership proof. Windows startup/transparent widget needs native support. Phone/TLS transport and notification infrastructure are not supplied by a WebView. Provider execution may spend subscribed quota. Quotas, sensors, progress and approvals must remain truthful.
14. **Acceptance gates.** Preserve all baseline tests and Ollama behavior; SQLite reopen and event replay; tasks survive UI close/reload; only approval launches; concurrent jobs are independent; duplicate launch/stop races tested; invalid input/unknown projects/violated constraints fail closed; stop only owned sessions. Then real provider checks in order: exact file + disk read-back; hello.py stdout `BUNNY_A_OK` and exit 0; small-file summary; tiny edit + relevant test. Typecheck/build, dev and production desktop/mobile render with clean console. Native widget startup and actual paired Android tests require their own evidence; never substitute web screenshots or mocks.
